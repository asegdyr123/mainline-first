# 按任务需要分配模型能力

只在实际需要委派、调整能力等级，或用户明确要求成本统计时加载。优先保证判断质量、交付质量和主线推进；成本优化是辅助安排，不需要安装路由器、改写用户模型配置或新增外部服务。

## 路由条件

先确保能力能够承担任务，再考虑工作量与交接开销。任务很长不等于需要高推理；“写代码”也不等于低能力足够。

1. 当前工具能直接完成的短操作直接做，包括少量搜索、抽取、简单编辑和执行明确命令。
2. 主模型先处理真正的分歧：目标和取舍、接口/数据契约、关键不变量、实验选择与验收方式。规格已经清楚时，不重新开一轮规划。
3. 存在足够大的、边界清楚的执行单元，且交接预计划算时，委派给能胜任的较低成本模型或较低推理等级。对需要创造性或跨模块判断的实现，保留足够能力。
4. 执行者产出结果和必要证据，主模型复核关键差异、约束和结论。没有新问题就验收并继续主线。执行者也遵守主 skill 的验证准入规则，不能为了提交完整报告自行追加测试。

宿主若只提供同模型子代理，委派仍可能改善上下文隔离，但不能称为已经实现低成本模型分工。若不能设置推理强度，也不要把文字里的“low”当成已生效的工具配置。

## 能力与配置边界

- 先看当前工具的可用模型、允许的推理等级和参数；用户已有明确分工或项目配置时先遵循适用约束。不能把某个客户端的参数直接套到另一个客户端。
- 若工具支持独立上下文，给执行者必要的材料与约束，并选择独立上下文。当前工具若要求使用 `fork_turns="none"` 才能覆盖模型，就遵守这个要求；不要给继承全部历史的分支附带无效的模型覆盖。
- 不固定模型代际或价格排名。以当前可用能力、已知表现和实际成本信息作判断；不为一次机械工作额外启动一整套模型评测。
- 用户选定的主模型继续负责最终决定。若当前主模型不适合某个关键问题，明确能力需求并使用实际允许的专家委派；不要生成一个新的“经理代理”再层层管理。
- 无可用较低成本路由时，当前模型直接工作。只有这会实质阻碍用户目标时才说明，不反复要求用户切模型。
- 执行者不能自行递归生成代理、扩大修改范围、开展额外实验或作新的产品/研究取舍。

## 一个完整工作单元的交接

只填影响本任务的内容；已有任务协议时不重复建立表格。

```text
角色：执行者；完成下面的工作，不再拆分代理。
目标与交付：……
必要背景和已定决策：……
工作区与允许改动的文件/资源：……
必须保留的接口、行为或证据边界：……
验收方式及可复用的现有结果：……
停止/回报条件：遇到规格冲突、需要扩大范围或重复失败时，返回具体问题与证据。
返回：产物位置、关键改动、实际检查与结果、尚需决定的问题；不返回整份日志。
```

完成标准可以是合格的最终产物，不要求每个任务都附验收命令。确需行为验证时，可以交给执行者选择针对性检查；不能把用户目标与完成标准留空，让其重新决定整个任务。

## 何时升级

| 信号 | 处理 |
|---|---|
| 一个可定位的语法或拼写错误 | 原执行者修正，复查受影响项 |
| 规格含糊、接口冲突、需要新的产品或研究决策 | 返回主模型补全决定，再继续 |
| 同一问题反复失败，普通定位未能解释 | 先核对任务边界与证据；若确需更强推理，升级这一工作单元 |
| 安全不变量、并发、迁移或核心算法依赖细致判断 | 从开始就选足够能力，不靠低能力反复碰运气 |
| 执行完成且关键证据完整 | 主模型验收；不固定另派一个高强度审查者 |

默认一个写入者。只有相互独立的工作才并行，明确文件/资源所有权；不要让多个代理同时操作同一活跃应用或互相覆盖产物。相关修复继续使用原执行者，减少冷启动与重复解释。等待优先使用事件机制并遵守宿主更新要求。

## 怎样判断是否省成本

只有用户要求成本审计时，才读取宿主提供的用量；记录不到的部分标为未知。观察到浪费时先纠正无效工作，不自动启动另一项成本测量任务。

```text
总 token = 主模型 input + output + 所有子代理 input + output
总费用 = 按实际模型/缓存/计费模式分别计算的费用之和
```

推理 token 通常属于输出用量、缓存输入属于输入的子集；按提供方实际口径核对，不能重复相加。没有记录的子代理、尚未结束的响应或当前最终答案，不能冒充已包含。

交接、返工和复核会产生真实 token，已经体现在对应输入输出中，不再重复加一次；它们在设计路由时是必须估计的成本来源。较低单价能够降低费用，却未必降低总 token；缩短回答也未必减少总工作量。

只有任务、起始上下文、完成标准和验收质量可比，才比较两种路由的总用量或费用。不用单次结果、模型名称或外部仓库宣称的百分比承诺长期节省。
