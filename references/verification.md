# 检查是否真正有必要

只在一个具体检查的必要性或范围存在实质疑问时读取。先说明它要解决的问题；不要先选择一套测试，再寻找理由。

## 先问缺少哪项判断

把疑问落到用户需要的行为或结论上。例如“修改导出逻辑后，多关节数据是否仍完整写出”是具体问题；“还需要提高可靠性”没有指出要解决什么。

现有差异、产物、日志或数据足以回答时，直接作判断。它们不足时，再选一个能补足该缺口的检查。用户和项目明确要求的检查仍需执行。

## 选择能回答问题的证据

| 实际问题 | 适合的处理 |
|---|---|
| 修改规则、文案、方案的逻辑与表达 | 阅读相关原文和改稿，判断问题是否得到解决；不自动生成测试脚本和情境套件 |
| 新功能或修复的真实行为尚未确认 | 执行有代表性的受影响路径，检验要求和关键失败；按影响选回归范围 |
| 故障原因不清 | 利用已有错误现场定位，必要时用有区分力的检查排除解释；不重复盲改和重跑 |
| 一个实验会决定采用哪个方案 | 在可比条件下检验该假设，获得作决定所需的信息后继续 |
| 真实接口、设备或环境暂不可用 | 完成能做的实现和判断，指出具体缺口；替代环境的结果只支持相应范围 |

不要把上表变成必走阶段。一个完整关键流程已经回答问题，就没有必要再用若干弱检查重复证明。

## 识别四类无效检查

1. **同义自证**：根据自己写的规则编写“期望行为”，再确认规则提到了这些行为。它不能证明模型在真实任务中会遵守规则。
2. **代理指标代替结果**：用可解析、条目齐全、字数合适、文件一致、检查通过等容易统计的属性，替代用户真正关心的内容或行为质量。某个属性是明确交付要求时才检查它。
3. **重复覆盖**：同一问题已被有效证据回答，又追加导入、冒烟、小样本、离线或另一份脚本检查。只有新增具体失败或明确要求才扩大。
4. **替代环境套娃**：真实行为尚未确认，就不断增加 mock 与局部测试，最后以通过数量制造可信感。准确说明证据范围并继续可做部分。

一次必要的格式或可执行性检查可以排除相应错误，结论只到这里。不要将它包装成内容质量、策略正确性或长期效果的证明。

## 复用与结束

已有证据是否失效，取决于影响该结论的代码、依赖、配置、数据和环境是否变化。只核对相关条件，不为复用证据新增一轮全面盘点。执行者给出的证据对应当前产物且完整时，主模型可以采用，不要求重跑一遍。

必要检查完成后返回交付；不要临近收尾再找检查来填充最终汇报。最终回答只在结果需要时说明关键验证或缺口。

研究中的重复试验可能用于估计方差、可靠性或泛化，这是有具体问题的工作。按需要执行，不能套用“最多两轮”之类统一限制。等待运行中的工作时复用状态和事件通知，无新信息不反复读取或播报。
